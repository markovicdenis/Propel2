# Index Naming

Propel auto-generates index names when an `<index>` or `<unique>` tag has no explicit `name`.

Recent changes make those generated names safer on databases with shorter identifier limits, especially PostgreSQL with its 63-character limit.

## `shortName` For Table Prefixes

Tables can now define an optional `shortName` attribute:

```xml
<table name="sportsbook_transactions" shortName="sbtx">
    <unique>
        <unique-column name="provider"/>
        <unique-column name="type"/>
        <unique-column name="user_id"/>
        <unique-column name="bet_transaction_id"/>
        <unique-column name="bet_order_id"/>
    </unique>
</table>
```

When Propel auto-generates an index name, it uses:

- `shortName` if present
- otherwise the table's normal name

With the example above, the generated unique index name starts with `sbtx_` instead of `sportsbook_transactions_`.

## Why This Exists

Without a shorter table prefix, a readable generated name like:

```text
sportsbook_transactions_provider_type_user_id_bet_transaction_id_bet_order_id_uniq
```

can exceed PostgreSQL's identifier length limit and require shortening.

Using `shortName` gives schema authors control over the most repetitive part of the generated name while keeping the column list readable.

## Fallback Shortening

If the final generated name is still longer than the platform limit, Propel now shortens it deterministically instead of doing a blind truncation.

The shortening logic:

- keeps as much readable prefix as possible
- appends a stable 6-character hash
- preserves `_idx` or `_uniq` for auto-generated names

Example shape:

```text
sbtx_provider_type_user_id_bet_transaction_id_2f4c9a_uniq
```

This avoids collisions between long names that only differ near the end.

## Scope

This behavior currently applies to index names generated by `Propel\Generator\Model\Index`.

- Auto-generated index names use `shortName` when present.
- Explicitly named indexes keep the provided base name, but are still normalized to the platform length limit if needed.
- Foreign key names are not affected by `shortName`.

## XML Support

The `shortName` attribute is part of the table schema definition and is emitted again by the XML dumper, so schema round-trips preserve it.
